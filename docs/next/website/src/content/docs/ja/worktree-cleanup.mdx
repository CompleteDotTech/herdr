---
title: マージ済み worktree の自動クリーンアップ
description: エージェントやツールをまたいで、検証済みのマージ済み worktree とローカルブランチをバックグラウンドで削除します。
---

Herdr のバックグラウンドランタイムは、登録済み Git リポジトリのマージ済み作業を確認します。クリーンアップはプログラムで実行され、モデル呼び出し、エージェントへのプロンプト、ツールごとのフック設定には依存しません。通常の Git コマンドで作成した worktree も対象です。

## クリーンアップの実行時期

ランタイムはセッションで開いたリポジトリを登録し、起動後、セッション所有権の変更時、Git 参照の変更検出時、定期的に確認します。重複する要求はまとめられます。ランタイムの稼働中は少なくとも 5 分ごとに調整を実行し、失敗時は最大 1 時間までのバックオフで再試行します。クライアントの切断後もランタイムとクリーンアップサービスは動作し続けます。

別のリポジトリは明示的に登録できます。

```sh
herdr worktree cleanup register /path/to/repository
```

登録したリポジトリにはグローバルな自動ポリシーが適用されます。まず確認したい場合は、登録前にグローバルポリシーを無効にしてください。

## 削除の対象

クリーンアップは設定済みの統合ブランチ、またはリモート既定ブランチを取得します。候補コミットがそのブランチに取り込まれたことを検証します。GitHub の squash/rebase マージでは、認証済みの `gh` が正確な候補ソースコミット、統合先、取り込まれたマージコミットを確認する必要があります。証拠が得られない、または曖昧な場合は候補を保持します。

プライマリチェックアウト、保護ブランチ、ロック済み worktree、明示的な保持例外は残ります。エージェントが idle の場合やクライアントが切断された場合でも、ライブまたは再開可能なセッションは所有権を維持します。追跡済み変更、未追跡・無視ファイル、サブモジュール、未完了の Git 操作、変更を隠し得るインデックスフラグも保持します。

自動削除はエージェントを停止せず、worktree の強制削除、リモートブランチ削除、Git garbage collection を行いません。ローカルブランチは削除直前に期待コミットを検証します。

Linux ではプロセスの作業ディレクトリとオープンファイル記述子も検査します。可視性が不完全な場合は worktree を保持します。他のプラットフォームでは完全なプロセス使用状況を確認できないため worktree を保持しますが、検証済みで未使用のローカルブランチは削除できます。リポジトリロックは協調するランタイムを調整します。外部のファイルシステム書き込みはロックに従わないため、状態を再確認できない場合は延期します。

## 状態の確認とクリーンアップ要求

```sh
herdr worktree cleanup inspect
herdr worktree cleanup preview /path/to/repository
herdr worktree cleanup run /path/to/repository
```

パスを省略すると、登録済みリポジトリをすべてプレビューまたは調整します。プレビューは削除せずに適格性を評価しますが、Git メタデータの取得と判断の記録は行えます。

コマンドは JSON を出力します。変更やプレビューのコマンドは、キューに入れた操作を最大 5 分待機します。タイムアウト時は操作が保留されるため、再試行前に ID を inspect してください。サーバー再起動で操作 ID は無効になりますが、リポジトリの耐久性のある記録は次の調整まで残ります。

結果には判断、コミット ID、マージ証拠、保持理由が含まれます。クライアントは `worktree.cleanup` イベントを受け取り、リソースが削除された場合は接続中クライアントに簡潔な通知を表示します。通知設定はクリーンアップを無効にしません。

## ポリシーと保持

グローバルポリシーと登録情報は Herdr の設定ディレクトリの `cleanup/settings.json` に保存されます。名前付きセッション間で共有され、リポジトリごとのオーバーライドはそのリポジトリのグローバルポリシーを置き換えます。

ポリシー JSON を作成して適用します。

```json
{"enabled": true, "remote": "origin", "integration_branch": null, "protected_branches": ["main", "master", "develop", "development", "trunk"], "retained_branches": ["release/keep-for-review"], "retained_worktrees": [], "github_merge_evidence": true}
```

```sh
herdr worktree cleanup configure policy.json
herdr worktree cleanup configure repository-policy.json /path/to/repository
```

保持する worktree には正規化された絶対パスを使います。`enabled` を `false` にすると自動クリーンアップが無効になります。手動の `run` も無効設定を尊重し、プレビューはポリシー上の除外を報告します。保持例外を削除してポリシーを再適用すると、後の削除を許可できます。フィールドを省略した場合は保護の既定値が適用され、リストを指定するとそのリストで置き換わります。

## API と復旧

個別に広告される `worktree.cleanup` JSON API メソッドは、`inspect`、`register`、`preview`、`reconcile`、`configure` の `action` を受け取ります。パスを使う操作には `repository`、設定には `policy` を使います。inspect は現在のスナップショットを返します。それ以外は `operation_id` を返すため、その ID が完了または失敗するまでスナップショットの `operations` を確認します。再起動検出には `boot_id` を使います。

削除意図と完了済みステップは、リポジトリの Git common directory 内の `herdr-cleanup/records.json` に保存されます。`herdr-cleanup/audit.jsonl` にはタイムスタンプ付きの操作記録を残します。削除前に状態を耐久的に公開します。worktree 削除とブランチ削除の間にクラッシュした場合、次回の調整では実際の Git 状態を確認し、残ったブランチを新たに検証します。再利用された名前や再作成されたパスは、過去の削除判断を引き継ぎません。

監査内のコミット ID は診断に役立ちますが、後の Git オブジェクト期限切れからの復旧を保証するものではありません。ローカルファイルや所有権の除外は条件が解消するまで保留されます。クリーンアップは進行のためにそれらのファイルを破棄しません。
